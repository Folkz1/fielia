O jeito certo é criar um **bootloader operacional do FIEL IA**: poucos arquivos raiz que dizem quem manda, qual é o projeto, onde registrar coisas e como eu devo agir. O resto fica em pastas específicas.

Eu faria assim:

```bash
mkdir -p ~/fiel-ia/{decisoes,contexto,operacoes,conteudo,produto,comunidade,legal,assets}
cd ~/fiel-ia
touch BOOTLOADER.md inbox.md ideas.md log.md
```

Estrutura:

```text
~/fiel-ia/
  BOOTLOADER.md       # contexto mínimo que eu devo ler primeiro
  inbox.md            # links, notas soltas, “salva isso”
  ideas.md            # ideias ainda não decididas
  log.md              # registro operacional resumido
  decisoes/           # decisões tomadas
  contexto/           # mercado, Corinthians, concorrentes, usuário
  produto/            # roadmap, features, bugs, UX
  conteudo/           # posts, campanhas, copy, calendário editorial
  operacoes/          # processos, checklists, lançamentos
  comunidade/         # personas, feedbacks, grupos, conversas
  legal/              # riscos, termos, privacidade, compliance
```

- Você diz “ideia:” → eu adiciono em `ideas.md`.
- Você diz “processo:” → eu documento em `operacoes/`.
